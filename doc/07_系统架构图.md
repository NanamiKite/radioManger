# 系统架构图

图中实线表示已接通的数据路径。GitHub 文件同步和邮件发送没有接入业务链路，未画为可用外部服务。字段、端点和运行步骤分别见[数据库](02_数据库设计说明.md)、[API](03_API设计说明.md)和[部署文档](06_部署说明.md)。

## 1. 整体系统架构

```mermaid
flowchart TB
    Client[浏览器或桌面窗口] --> UI[Vue 3 页面]
    UI -->|同源 REST| API[FastAPI 路由与认证依赖]
    UI <-->|同源 WebSocket| Realtime[DX Cluster 与 UDP 路由]
    API --> Services[业务服务]
    Services --> ORM[SQLAlchemy]
    ORM --> DB[(SQLite 或 MySQL)]
    API -->|MySQL 令牌黑名单| Redis[(Redis)]
    Services --> QRZ[QRZ XML 查询]
    Realtime --> DX[进程内 DXClusterManager]
    DX <-->|Telnet| Node[DX Cluster 节点]
    UDP[无线电软件 UDP 数据] --> Listener[进程内 UDPListenerService]
    Listener --> Realtime
    UI --> Tiles[OpenStreetMap 底图]
```

呼号缓存位于 SQL 数据库。Telnet 连接、UDP 监听与广播在后端进程内共享，不按用户分配实例。

## 2. 三种部署结构

### 2.1 纯本地部署（SQLite）

```mermaid
flowchart LR
    Browser[浏览器] --> Vite[Vite 5173]
    Vite -->|API、health 与 WS 代理| API[FastAPI 8000]
    API --> DB[(SQLite 文件)]
```

本地发布包另由 `release_server.py` 在 8000 端口同时提供静态网页和 API，不需要 Vite。pywebview 通过本机 HTTP URL 加载页面；Electron 配置本身不提供 Python 后端。

### 2.2 局域网部署（Docker + MySQL）

```mermaid
flowchart LR
    Browser[局域网浏览器] --> Nginx[Nginx 80]
    Nginx -->|API、health 与 WS| API[FastAPI 单 worker]
    API --> MySQL[(MySQL)]
    API --> Redis[(Redis 黑名单)]
```

Nginx 直接提供构建后的前端。现有容器配置需按部署文档补充 `/health` 转发。

### 2.3 云服务器部署

```mermaid
flowchart LR
    Browser[浏览器] -->|HTTPS 与 WSS| TLS[TLS 入口]
    TLS --> Static[前端静态资源]
    TLS -->|API、health 与 WS| API[FastAPI]
    API --> DB[(MySQL)]
    API --> Redis[(Redis)]
```

TLS 由部署方配置；数据库和缓存不需要直接向浏览器暴露。

## 3. 前端架构

```mermaid
flowchart TB
    Main[main.ts 注册插件] --> App[App.vue 布局]
    App --> Router[Vue Router 与页面守卫]
    Router --> Views[业务页面]
    Views <--> Stores[Pinia：auth、logs、stats、dxcluster]
    Views --> API[api 模块]
    Stores --> API
    API --> Axios[同源 Axios 与 Bearer token]
    API --> Fetch[导出文件 fetch]
    API --> WS[同源 WebSocket]
    Stores --> Storage[localStorage 登录信息]
```

语言和主题也有本地偏好存储。页面守卫用于导航，后端仍负责实际认证。

## 4. 后端架构

```mermaid
flowchart TB
    Request[HTTP 请求] --> Rate[IP 限流]
    Rate --> Logging[请求日志]
    Logging --> Error[异常处理]
    Error --> CORS[CORS]
    CORS --> Routes[API 路由]
    Routes --> Auth[认证依赖与管理员依赖]
    Routes --> Service[业务服务]
    Auth --> Session[请求数据库会话]
    Service --> Session
    Session --> ORM[ORM 模型]
    ORM --> DB[(数据库)]
```

这是普通 HTTP 请求路径。WebSocket 使用各端点独立的连接认证逻辑，不经过相同的 HTTP 中间件链。

## 5. 数据库架构

```mermaid
erDiagram
    users ||--o{ stations : owns
    users ||--o{ locations : owns
    users ||--o{ qso_logs : owns
    stations ||--o{ locations : contains
    stations ||--o{ qso_logs : groups
    locations o|--o{ qso_logs : references
    users ||--o{ deleted_logs : owns
    users ||--o| statistics : snapshot
    users ||--o{ log_files : imports
    users ||--o{ sync_history : records
    users ||--o{ audit_logs : acts
    users ||--o{ user_sessions : sessions
    users o|--o{ system_configs : updates
```

`callsign_cache` 为独立共享表。`deleted_logs.log_id` 保存原 QSO ID，但没有外键约束。审计、会话和系统配置的用户外键不统一使用 CASCADE。

## 6. 台站—位置—日志关系

```mermaid
flowchart LR
    User[用户] --> A[台站 BA7ABC]
    User --> B[台站 BH8XYZ]
    A --> Home[Home 位置]
    A --> Field[Field 位置]
    B --> Mobile[Mobile 位置]
    Home -->|激活位置可补全字段| QSO[QSO 日志]
    QSO -->|必填外键| A
```

台站保存呼号，位置保存本台网格和设备。日志可保留自己的 `my_gridsquare`；导出按位置筛选时使用本网格前 4 位，不等同于日志位置外键。

## 7. 位置激活流程

```mermaid
sequenceDiagram
    participant UI as 台站页面
    participant API as locations API
    participant Service as LocationService
    participant DB as 数据库
    UI->>API: POST /locations/{id}/activate
    API->>Service: 当前用户与目标位置
    Service->>DB: 查询当前用户未删除的目标位置
    Service->>DB: 取消该用户所有位置激活状态
    Service->>DB: 设置目标 is_active=True 并提交
    DB-->>UI: 激活位置对象
```

首个位置在创建时自动激活。互斥规则由服务执行，没有数据库唯一约束。

## 8. 日志导入导出流程

```mermaid
flowchart TB
    File[ADI 或 ADIF 文件] --> Upload[校验后缀与 50 MiB 大小]
    Upload --> Parse[解析记录与映射字段]
    Parse --> Dedup[匹配当前用户日志的六字段键]
    Dedup --> Existing[已有 QSO：补空与确认状态更新]
    Dedup --> New[新 QSO：补全台站、网格与 DXCC]
    New --> Commit[每累计 500 条新记录提交]
    Existing --> Finish[提交剩余更改与导入元数据]
    Commit --> Finish
    Query[导出筛选条件] --> Read[查询日志并生成已支持字段]
    Read --> Download[返回完整 ADI 文件]
```

去重键为呼号、日期、开始时间、波段、模式、频率。导入按批提交；导出不包含所有数据库字段，因此文件往返不是无损备份。

## 12. DX Cluster 实时 Spot 架构

```mermaid
sequenceDiagram
    participant UI as DX Cluster 页面
    participant API as dxcluster API
    participant Manager as DXClusterManager
    participant Node as Telnet 节点
    UI->>API: POST /connect，host 与 port
    API->>API: 使用激活位置所属台站的呼号
    API->>Manager: connect
    Manager->>Node: 连接并以呼号登录
    API-->>UI: 状态
    UI->>API: WebSocket /ws?token=...
    API-->>UI: 逐条推送最多 100 条历史 spot
    loop 实时广播
        Node->>Manager: spot 文本
        Manager->>Manager: 解析并放入最多 100 条缓冲
        Manager-->>UI: type=spot
    end
    Node-->>Manager: 断开
    Manager-->>UI: type=disconnect
```

Telnet 不自动重连。前端重连 WebSocket 只恢复消息通道。管理器的连接、切换和断开影响同进程所有订阅者。

## 13. 回收站流程

```mermaid
flowchart TB
    Delete[删除单条日志或台站] --> Backup[写 deleted_logs 快照与 7 天到期时间]
    Backup --> Soft[原 QSO 标记 is_deleted=True]
    Soft --> List[列表只展示未恢复、未到期条目]
    List --> Restore[请求恢复]
    Restore --> Original{原 QSO 是否存在}
    Original -->|是| Clear[取消原记录软删除]
    Original -->|否| Rebuild[从 JSON 快照重建]
    Clear --> Mark[回收站条目标记已恢复]
    Rebuild --> Mark
    List --> Remove[清空、批量删除或过期清理]
    Remove --> Entry[只删除回收站条目]
```

恢复日志不自动恢复台站和位置。过期条目没有后台定时任务清理；部分回收站操作会触发清理函数。

## 14. 文字版架构图

```text
页面 / Pinia / API 客户端
            │
            ├─ HTTP ─→ 代理 ─→ 路由 + JWT 依赖 ─→ 业务服务 ─→ SQLAlchemy ─→ SQLite / MySQL
            │                      │
            │                      └─ MySQL JTI 黑名单 ─→ Redis（不可用时可回退内存）
            │
            └─ WebSocket ─→ 独立连接认证 ─→ 进程内 DX Cluster / UDP 广播
                                                   │
                                                   ├─ Telnet 节点

```

SQL 会话和业务数据按请求与用户访问，实时连接状态则以进程为单位共享。单 worker 是现有运行结构的一部分。

## 15. 主要场景数据流

### 15.1 用户登录与 Token 管理

登录生成 JWT；请求验证 JWT 和用户状态；MySQL 登出撤销当前 JTI 并删除会话。删除会话与撤销 JWT 是不同操作，SQLite HTTP 登出仅由客户端清除登录信息。

### 15.2 QSO CRUD 与回收站

创建日志时补全激活位置、UTC 日期时间和 DXCC；修改按请求字段更新；删除先快照再软删除；恢复优先恢复原记录。普通列表、统计和导出均过滤软删除日志。

### 15.3 ADI 文件导入

上传 → 解析 → 六字段匹配 → 新增或合并 → 分批提交 → 保存 `log_files` 元数据。导入元数据不保存原文件副本。

### 15.4 数据分析

QSO SQL 聚合 → DXCC/波段/模式响应 → Pinia → 图表。点击 DXCC 或波段后，把筛选条件写入日志页 URL。DXCC 图表的确认口径为 LoTW，概览口径为纸质 QSL 或 LoTW。

### 15.5 服务器管理

管理员页面 → `get_current_admin` → 用户/系统服务 → 数据库。管理员路由在 SQLite 模式不注册；后台系统配置与环境 Settings 是不同来源，写入配置表不代表所有运行开关已经接入。

### 15.6 UDP 接收与保存

```mermaid
sequenceDiagram
    participant Radio as 无线电软件
    participant UDP as UDPListenerService
    participant UI as 已认证 WebSocket 客户端
    participant Log as LogService
    participant DB as 数据库
    Radio->>UDP: UDP 数据
    UDP->>UDP: 解析与字段转换
    UDP-->>UI: qso_received
    opt 客户端显式保存
        UI->>Log: POST /udp/save-to-log 或 WS action=save
        Log->>DB: 创建 QSO
        Log-->>UI: 日志 ID 或 qso_saved
    end
```

现有日志页收到广播后刷新列表并提示，不自动发起保存。
