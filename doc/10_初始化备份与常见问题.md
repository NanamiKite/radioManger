# 初始化、备份与常见问题

数据库初始化、备份恢复、启动脚本说明和部署常见问题，适用于[本地](07_本地部署.md)、[服务器](08_服务器部署.md)与 [Windows/Android](09_Windows与Android部署.md) 各部署方式。

## 1. 数据库初始化

在 `backend/` 读取正确的 `.env` 后运行：

```bash
python -m app.scripts.init_db
```

新数据库执行 Alembic 完整迁移链 `000000000001`（12 张表）→ `5eed5637c7eb`（`users.role` 长度调整）。已标记版本的库先校验结构，再升级。迁移失败立即退出，不会把失败库标记为 head。应用导入时不自动建表。

旧版 `create_all` 创建、没有版本号的数据库必须先备份，再显式接管：

```bash
python -m app.scripts.init_db --adopt-legacy
```

接管会比对表、列、类型、索引和约束，仅在匹配已知基线或 head 时登记版本；结构不匹配则拒绝并报告差异。发现跨用户台站/位置关联时只报告数量。首次迁移后所有旧令牌需要重新登录。

初始化不创建默认账户。个人使用在网页注册；管理员由操作员显式创建：

```bash
python -m app.scripts.create_admin
```

脚本读取 `ADMIN_USERNAME`、`ADMIN_PASSWORD`、`ADMIN_EMAIL`，未设置密码时隐藏输入。密码至少 8 字符且最多 72 个 UTF-8 字节。已有普通用户占用管理员用户名时会拒绝。Compose 只有显式设置 `ADMIN_PASSWORD` 时才在迁移后调用该命令。

## 2. 备份与恢复

SQLite 使用 WAL，运行中只复制 `.db` 可能遗漏未合并数据。可使用 Python 标准库在线备份，路径替换为实际值：

```python
import sqlite3

with sqlite3.connect("/absolute/path/radiomanager.db") as source:
    with sqlite3.connect("/absolute/path/backup.db") as target:
        source.backup(target)
```

也可以正常停止所有写入进程后做离线备份。恢复时先停止应用，保存现有文件，再替换为备份并检查日志数与抽样记录。MySQL 使用一致性数据库备份工具，保存并验证备份文件；不要直接复制运行中的数据库数据目录。

ADI 导出不包含全部数据库字段和关系，不能替代完整备份。数据同步与邮件服务目前仅保留接口骨架，暂未接入真实传输（TODO）。

## 3. 启动脚本说明

| 脚本 | 实际用途 |
| --- | --- |
| `start-local.sh` | 初始化后启动 Vite 与 Uvicorn，读取现有配置 |
| `start-dev.sh` | 同上；以 shell 中的 `DATABASE_MODE` 选择模式，未设时导出 `sqlite` |
| `start-server-mode.sh` | 从现有 `backend/.env` 读取 MySQL 配置，迁移后启动；不覆盖配置 |
| `start-prod.sh` | 使用 `docker compose` 启动组合，外部网页/API 入口为 80 端口 |
| `start-windows-local.bat` | Windows 源码依赖安装、初始化与 Vite/Uvicorn 启动 |
| `start-windows-web.bat` | 前端/Electron 选项；API 地址输入未接入客户端 |
| 发布包 `start.bat` | 运行 `release_server.py`，同源提供网页与 API |

## 4. 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 无法登录初始账户 | 没有默认密码；注册个人账户或显式创建管理员 |
| 启动时提示空密钥 | 在实际进程读取的 `.env` 设置持久 `SECRET_KEY` |
| 初始化后看不到数据 | 检查工作目录与 SQLite 绝对路径，保证初始化和服务连接同一文件 |
| 设置页模式不正确、管理入口不显示 | 从浏览器同源访问 `/health`，确认代理返回 JSON，而不是 SPA 页面 |
| API 可用但实时数据不更新 | 检查 WebSocket Upgrade 转发，HTTPS 页面须使用 `wss` |
| 导入出现 413 | 同时检查 Nginx 上传限制和 API 的 50 MiB 限制 |
| 页面刷新出现 404 | 为 History 路由配置 `index.html` 回退，API 路径单独代理 |
| 健康检查返回 503 | 查看 `subsystems.database`，恢复数据库连接后重试 |
| UDP 没有数据 | 确认当前账户拥有监听，发送到后端主机；检查绑定地址、来源白名单与端口 |

Docker Compose 未映射 UDP 端口。容器需要接收外部广播时，另外映射使用的端口，例如 `2237:2237/udp` 和 `12060:12060/udp`；收到广播后日志不会自动保存，见 [UDP API](04_API端点说明.md#十五udp-模块apiv1udp)。

升级前从旧 `.env` 删除 `REDIS_URL`、`REFRESH_TOKEN_EXPIRE_DAYS`、`ENABLE_TEST_ACCOUNT` 和 `TEST_ACCOUNT_*`，设置 `WORKERS=1`。发布包继续使用包根目录 `.env` 与原数据库路径；首次缺少密钥时生成并保存，已有密钥不覆盖。
