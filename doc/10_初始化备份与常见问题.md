# 初始化、备份与常见问题

数据库初始化、备份恢复、启动脚本说明和部署常见问题，适用于[本地](07_本地部署.md)、[服务器](08_服务器部署.md)与 [Windows/Android](09_Windows与Android部署.md) 各部署方式。

## 1. 数据库初始化

推荐入口为 `python -m app.scripts.init_db`：

1. 新数据库通过 ORM 创建所有表，再尝试标记 Alembic head。
2. 已有表时尝试执行迁移；当前脚本在迁移失败后还可能尝试 stamp，因此版本标记不能单独证明结构已升级。
3. MySQL 模式读取 `ADMIN_*` 创建管理员；SQLite 仅在 `ENABLE_TEST_ACCOUNT=true` 时创建测试账户。

当前唯一迁移仅调整 `users.role`，不包含从空库建表。已有数据升级前先备份并检查实际迁移，不要把 stamp 当作结构修复。

手动创建管理员可在 `backend/` 配置 `ADMIN_USERNAME`、`ADMIN_PASSWORD`、`ADMIN_EMAIL` 后运行：

```bash
python -m app.scripts.create_admin
```

该脚本会输出初始凭据，应在受控终端执行。普通应用入口 `app.main` 自动建表，但不自动创建账户；发布入口 `release_server.py` 有单独的账户创建逻辑。

## 2. 备份与恢复

SQLite 使用 WAL，运行中只复制 `.db` 可能遗漏未合并数据。可使用 Python 标准库在线备份，路径替换为实际值：

```python
import sqlite3

with sqlite3.connect("/absolute/path/radiomanager.db") as source:
    with sqlite3.connect("/absolute/path/backup.db") as target:
        source.backup(target)
```

也可以正常停止所有写入进程后做离线备份。恢复时先停止应用，保存现有文件，再替换为备份并检查日志数与抽样记录。MySQL 使用一致性数据库备份工具，保存并验证备份文件；不要直接复制运行中的数据库数据目录。

ADI 导出不包含全部数据库字段和关系，不能替代完整备份。GitHub 同步仍为预留实现。

## 3. 启动脚本说明

| 脚本 | 实际用途 |
| --- | --- |
| `start-local.sh` | 初始化后启动 Vite 与 Uvicorn，读取现有配置 |
| `start-dev.sh` | 同上；以 shell 中的 `DATABASE_MODE` 选择模式，未设时导出 `sqlite` |
| `start-server-mode.sh` | 本机 MySQL 调试，会覆盖 `backend/.env`，含固定测试凭据 |
| `start-prod.sh` | 包装旧版 `docker-compose` 命令；实际网页端口以 Compose 为准 |
| `start-windows-local.bat` | Windows 源码依赖安装、初始化与 Vite/Uvicorn 启动 |
| `start-windows-web.bat` | 前端/Electron 选项；API 地址输入未接入客户端 |
| 发布包 `start.bat` | 运行 `release_server.py`，同源提供网页与 API |

## 4. 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 无法登录初始账户 | 确认是否执行账户初始化；默认源码环境没有测试账户 |
| 启动时提示空密钥 | 在实际进程读取的 `.env` 设置持久 `SECRET_KEY` |
| 初始化后看不到数据 | 检查工作目录与 SQLite 绝对路径，保证初始化和服务连接同一文件 |
| 设置页模式不正确、管理入口不显示 | 从浏览器同源访问 `/health`，确认代理返回 JSON，而不是 SPA 页面 |
| API 可用但实时数据不更新 | 检查 WebSocket Upgrade 转发，HTTPS 页面须使用 `wss` |
| 导入出现 413 | 同时检查 Nginx 上传限制和 API 的 50 MiB 限制 |
| 页面刷新出现 404 | 为 History 路由配置 `index.html` 回退，API 路径单独代理 |
| 健康检查 200 但服务异常 | 读取 `status` 和 `subsystems`，不能只看 HTTP 状态 |
| UDP 没有数据 | 数据发往后端主机，确认监听已启动并允许目标 UDP 端口 |

Docker Compose 未映射 UDP 端口。容器需要接收外部广播时，另外映射使用的端口，例如 `2237:2237/udp` 和 `12060:12060/udp`；收到广播也不代表日志已经保存，见 [UDP API](04_API端点说明.md#十五udp-模块apiv1udp)。
