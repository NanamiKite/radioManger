# 后端架构设计

## 后端技术栈

后端使用 FastAPI 和 Uvicorn，SQLAlchemy 2 访问 SQLite/MySQL，Pydantic 2 校验请求与序列化响应。配置由 pydantic-settings 加载，认证使用 PyJWT 与 passlib/bcrypt，数据库迁移使用 Alembic。

依赖版本以 [`requirements.txt`](../backend/requirements.txt) 为准。Docker 使用 Python 3.12；源码环境也可按该版本准备。

## 项目结构

| 路径 | 职责 |
| --- | --- |
| [`app/main.py`](../backend/app/main.py) | 注册模型、建表、应用生命周期、中间件与路由 |

| `app/api/v1/` | HTTP 参数、认证依赖、状态码和响应 |
| `app/schemas/` | Pydantic 请求与响应模型 |
| `app/services/` | 业务操作、聚合、外部访问与长连接 |
| `app/models/` | 12 张业务表的 ORM 定义 |
| `app/database/` | SQLAlchemy 引擎、SessionLocal、get_db |
| `app/dependencies.py` | Bearer JWT 与用户状态校验 |
| `app/dependencies_admin.py` | 管理员权限依赖 |
| `app/middleware/` | 限流、日志、异常处理 |
| `app/utils/` | ADIF、呼号、DXCC、网格、距离、JWT 工具 |
| `app/scripts/` | 数据库初始化和管理员创建 |
| `alembic/` | 迁移环境与版本 |
| `release_server.py` | 发布入口、内置账户创建、前端静态资源 |

| `run.py` | Uvicorn 启动包装 |

请求的主要路径为“路由 → 服务 → ORM → 数据库”。认证是路由依赖，不是独立的认证中间件。多数服务使用同步 SQLAlchemy Session，在方法内部提交。

## 配置管理（config.py）

`Settings` 从环境变量和进程工作目录下的 `.env` 读取配置，变量名区分大小写，环境变量优先。列表配置如 `CORS_ORIGINS` 使用 JSON 数组。

`ACTIVE_DATABASE_URL` 在 SQLite 模式返回 `SQLITE_URL`，其余分支返回 `DATABASE_URL`。部署应只使用约定的 `sqlite/mysql`。MySQL 模式缺少 URL 会退出；生产环境缺少 `SECRET_KEY` 也会退出。非生产环境允许临时生成密钥，重启后旧令牌将无法验证。

`DEBUG` 控制 Swagger 与 ReDoc 页面，不控制日志级别或 CORS。`WORKERS` 不会覆盖命令行 Uvicorn 的 worker 参数。完整变量表见[本地部署](07_本地部署.md#环境变量配置)。

## 认证系统

注册通过 `UserService` 校验密码一致性并保存 bcrypt 哈希。登录生成两个带 `sub`、`exp`、`jti` 的 JWT，默认 access token 7 天、refresh token 30 天；没有令牌刷新端点。

HTTP 请求由 `get_current_user` 验证签名、过期时间、用户存在性及启用/删除状态。MySQL 模式还检查令牌黑名单，并更新会话活跃时间。管理员依赖在此基础上检查角色。

MySQL 登出尝试把当前 JTI 加入黑名单，TTL 为令牌剩余有效期。黑名单优先使用 Redis，初始化连接失败时回退内存。SQLite HTTP 登出只返回成功，不撤销令牌。WebSocket 的独立认证逻辑会在连接时检查黑名单和用户状态。

`SessionService` 用于登录记录和在线统计。改密、管理员重置密码会删除会话行，但认证不要求对应行存在，不能把会话删除描述为已撤销所有旧令牌。

## 数据库引擎

[`database/base.py`](../backend/app/database/base.py) 创建全局 engine、Base 和 SessionLocal。SQLite 设置 `check_same_thread=False`，连接时启用 WAL 与外键；MySQL 设置连接池存活检查和 3600 秒回收。

`get_db` 为请求创建 Session，并在结束时关闭。业务异常后的回滚由实际服务路径决定，项目没有覆盖所有业务操作的统一事务包装。

导入 `app.main` 时会执行 `Base.metadata.create_all`。它可创建缺失表，不能修改已有列，也不能替代升级迁移。显式初始化脚本负责建表/迁移版本及账户创建，详见[数据库文档](02_数据库设计说明.md)。

## 台站与位置设计

`Station` 保存呼号，`Location` 保存操作地点和设备。一个用户可以有多个台站，一个台站可以有多个位置，QSO 同时关联用户、台站和可空的位置。

激活位置是服务层规则：取消该用户全部位置的激活状态后，再激活目标；首个位置自动激活。创建日志可从激活位置推断台站和本网格。该互斥规则没有数据库唯一约束。

## 业务逻辑服务

### 日志服务（LogService）

`create_log` 规范呼号并补全 UTC 日期、时间、DXCC 与激活位置信息。创建时若收到纸质 QSL 确认，会同时设置纸质、LoTW 和 eQSL 的发送/接收状态；`update_log` 不执行该联动。

列表支持台站、日期、波段、模式、呼号、对方网格和 DXCC 筛选，并用排序白名单限制动态列。`delete_log` 先备份回收站再软删除。`get_stats` 用聚合查询生成概览，不读取统计快照表。

### 台站服务（StationService）

创建时规范呼号，优先恢复同名软删除台站。删除时备份并软删除台站日志，再软删除位置和台站。恢复台站本身不会恢复位置和日志。日志备份与后续台站删除是独立提交，不是一个整体事务。

### 位置服务（LocationService）

提供位置列表、创建、更新、删除、激活和激活位置查询。位置删除仅设置 `is_deleted=True`，不会触发物理外键的 `SET NULL`。

### 回收站服务（DeletedLogService）

保存日志 JSON 快照、原 ID 和 7 天到期时间。恢复优先取消原记录的软删除，缺失原记录时才重建。到期、清空和批量删除均针对回收站条目；没有定时清理任务。

### 呼号查询服务（CallsignService）

依次尝试 30 天内数据库缓存、QRZ 在线查询、旧缓存和离线 DXCC 推断。仅在线结果写入缓存；离线推断不用于确认呼号注册信息。缓存是全局共享表，不是 Redis 缓存。

### 导入导出服务（ImportExportService）

`ADIParser` 按记录分割文件，再按标签长度提取字段。服务负责日期/时间转换、六字段去重、补空合并、确认状态更新与分批提交。去重覆盖当前用户所有台站，每累计 500 条新记录提交一次。

导出按查询逐批读取 ORM 记录，但在内存中拼接完整字符串，返回普通文件响应，不是端到端流式下载。导出字段有限，尤其不包含 QSL 状态，不能替代数据库备份。请求、字段范围和返回计数见[API 端点说明](04_API端点说明.md)。

### DX Cluster 服务（DXClusterManager）

每进程维护一个 asyncio Telnet 连接、最多 100 条 spot 和订阅队列。解析器从文本提取呼号、频率、波段等数据，队列把 spot 广播给 WebSocket 订阅者。

连接和切换由用户请求触发；Telnet 不自动重连。应用退出时 lifespan 关闭该连接。连接及 spot 在同一进程的用户之间共享。

### 统计服务（StatsService）

按波段、模式和 DXCC 聚合日志，生成实体×波段和波段×模式矩阵。概览由 `LogService` 提供。`refresh_statistics` 可保存统计快照，但常用路由不调用它。

概览与地图用纸质 QSL 或 LoTW 收到确认判断“已确认”，DXCC 图表只使用 LoTW。WAZ 统计没有完整实现。

### UDP 服务（UDPListenerService）

监听后端主机上的 WSJT-X 类数据与 N1MM XML UDP 数据，转换为 QSO 字段并广播 `qso_received`。默认端口为 2237、12060，监听由 API 显式启动；设置 `UDP_ENABLED` 不会自动启动监听。

接收不会自动保存；保存接口和 WebSocket `action=save` 才调用 `LogService`。监听状态与订阅客户端为进程内共享，部署需使用单 worker，并单独开放所需 UDP 端口。

### 管理与预留服务

| 服务 | 职责及边界 |
| --- | --- |
| `AdminService` | 用户查询、启禁用、重置密码、软删除和系统统计 |
| `AuditService` | 写操作审计；写入失败记录日志 |
| `SessionService` | MySQL 登录会话与近 15 分钟在线用户统计 |
| `ConfigService` | 初始化和保存后台配置项，不直接修改 Settings |
| `token_blacklist` | Redis 或进程内存的 JTI 黑名单 |
| `cache` | 工厂按模式选择 Redis 或内存 TTL 实现，呼号缓存另存于 SQL 表 |
| `EmailService` | 内存验证码，实际邮件发送未接入 |
| `SyncService` / `GitHubService` | 同步接口与历史，未接入真实文件推拉 |

## API 路由

常规路由模块为 `auth`、`users`、`logs`、`stations`、`locations`、`stats`、`callsigns`、`sync`、`shortcuts`、`dxcluster`、`map`、`udp`。另有服务器模式的 `admin`。端点详情集中维护在[API 端点说明](04_API端点说明.md)。

`/health` 查询数据库，MySQL 模式还查询 Redis；故障时返回 `status=degraded`，HTTP 状态仍为 200。健康检查还向 SQLite 设置页报告配置路径，不反查 engine 的文件路径。

## 中间件

普通 HTTP 请求执行顺序：

```text
RateLimitMiddleware → LoggingMiddleware → ErrorHandlerMiddleware → CORSMiddleware → 路由
```

限流按 IP 使用进程内 60 秒窗口：普通桶 100 次，敏感认证路径共用严格桶 5 次。请求日志记录方法、路径、状态和耗时。

错误中间件捕获自定义异常及未处理异常；FastAPI 自行处理的 HTTPException 和校验错误通常返回 `detail` 格式，因此错误响应并不完全统一。CORS 允许来源和方法由 `main.py` 配置，改变 JSON 文档不会改变运行行为。

## 测试

仓库有 `pytest.ini` 和 pytest 依赖，但没有 `backend/tests/` 用例目录。不能据此声称已有认证、日志或双数据库自动测试覆盖。前端构建和后端导入检查同样不能替代端到端部署验证。

## 运行约束

部署命令见[本地部署](07_本地部署.md)与[服务器部署](08_服务器部署.md)。

后端必须以单 worker 运行：DX Cluster、UDP、自定义快捷链接和内存限流都保存在进程内状态，多 worker 之间不共享。Dockerfile 已使用 `--workers 1`。数据库初始化和管理员创建入口见[初始化备份与常见问题](10_初始化备份与常见问题.md)。
