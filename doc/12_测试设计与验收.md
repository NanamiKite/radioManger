# 测试设计与验收

## 测试原则

测试以 `02`～`10` 设计文档的行为约定为预期。后端测试保留真实路由、认证、校验、中间件、服务和数据库，只把数据库连接指向测试库；外部 QRZ 在 HTTP 客户端边界模拟，UDP/Telnet 使用 loopback 服务。前端测试使用真实 Vue 页面和浏览器，接口响应在网络边界固定。

断言按状态码和字段精确校验，覆盖正常、拒绝、边界和生命周期场景。不使用 `xfail`、吞异常或放宽断言的方式通过。

## 设计约定

- 缓存和回收站的截止时刻未约定比较符号，测试用可控时钟分别验证期限内与期限后。
- 无法补全创建关联、过期恢复统一返回 422；批量呼号查询超过 50 个整体拒绝；UDP 越界输入在失焦时修正到边界。
- MySQL 权限分支在隔离数据库中运行，方言、连接池和迁移由真实 MySQL 用例验证。

## 运行命令

后端使用 Python 3.12 和 `backend/requirements.txt` 中固定的依赖。普通 API、WebSocket 和子进程用例使用内存或临时 SQLite：

```bash
cd backend
PYTHONPATH=. python -m pytest tests --ignore=tests/contracts/mysql -q
```

真实 MySQL 用例使用 loopback 上的临时实例，仅接受没有数据库路径的管理员 URL；每个用例创建随机 `radio_contract_<UUID>` 数据库，结束后删除。

```bash
# 先自行启动一次性的 MySQL 8 实例，并绑定到 127.0.0.1 的临时端口。
cd backend
RADIO_TEST_MYSQL_ADMIN_URL='mysql+pymysql://root:<测试密码>@127.0.0.1:<临时端口>' \
  PYTHONPATH=. python -m pytest tests/contracts/mysql -q
```

未提供该 URL 时 MySQL 测试报错。

浏览器测试使用独立依赖目录，通过登录表单建立会话，HTTP/WebSocket 在网络边界返回固定响应。默认启动独立 Vite 5179 端口，无重试，失败保留截图、trace 与视频：

```bash
npm --prefix frontend ci
npm --prefix frontend/tests ci
cd frontend/tests
npx playwright install chromium
npm test -- --workers=2
```

浏览器 HTML 报告位于 `frontend/tests/playwright-report/`，失败附件位于 `frontend/tests/test-results/`，均不进入版本控制。

## 测试范围

- SQLite 与 MySQL 各自有真实数据库用例；权限分支测试按模式参数运行。
- Windows/macOS 原生包、Android APK、云上 TLS 与公网 DX 节点需要人工或 CI 目标验证。
- 百分比按固定样本计算，允许最多 0.05 个百分点舍入误差。
- `band_worked` 只按 LoTW 验证已确认实体。

## 踩坑记录

- Vue I18n 把裸 `|` 当作复数分支分隔符，语言包改用字面量 `{'|'}`。
- MySQL 测试观察连接处于 `REPEATABLE READ` 旧快照，`expire_all()` 看不到另一条 HTTP 连接提交的数据；观察前先 `rollback()` 结束只读事务。
- Playwright 的成功提示选择器曾同时匹配“登录成功”和“设置保存成功”，改为精确匹配 `Settings saved`。

## GitHub Actions

### 日常 PR 检查

[`ci.yml`](../.github/workflows/ci.yml) 只在目标分支为 `main` 的 PR 上运行，不同时监听开发分支 push 或合并后的 push。同一 PR 更新会取消旧运行。范围按合并基线计算；删除和跨目录重命名同时覆盖原、新路径。

| 改动范围 | 自动检查 |
| --- | --- |
| 仅 Markdown 或 `doc/` | 只生成范围与汇总，不安装运行依赖或启动数据库 |
| 前端源码、资源、依赖 | `npm ci`、类型检查、Vite 构建 |
| 后端应用、迁移、依赖 | 既有 SQLite 回归 `tests/test_*.py`，以及独立真实 MySQL 测试 |
| 本地发布入口、桌面启动器 | 既有 SQLite 回归，不启动 MySQL |
| MySQL 专用测试 | 仅真实 MySQL 测试；共享测试 fixture 改动同时覆盖两种模式 |
| 打包脚本、代理或 Compose 配置 | 脚本语法、Compose 配置；打包脚本另核对版本，不构建原生包 |
| 工作流或 `scripts/ci/` | 语法、固定版本 actionlint、版本元数据 |

SQLite 与 MySQL 是独立 job；共享后端改动会同时验证服务器模式。分支保护可只要求稳定名称 `CI`。

### 手动目标验证

在 Actions 的 **Manual target validation → Run workflow** 选择分支与一个 `target`：

| target | 实际执行 |
| --- | --- |
| `web` | 类型检查与静态构建，保存 `dist` |
| `server` | 构建实际镜像，启动隔离 MySQL/FastAPI/Nginx；验证 SPA、资源、认证、QSO、ADI 导出、WebSocket 保存及重启后数据 |
| `windows-web` / `windows-desktop` | Linux 交叉打包，再在 Windows runner 用包内 Python 验证 SQLite、真实 HTTP 流程、密钥和数据持久化 |
| `macos` | 在 `macos-14` 构建，解压到临时目录，走实际 `start.sh` 的虚拟环境安装、启动和重启流程 |
| `contracts-sqlite` | 全部 SQLite/HTTP/实时/子进程测试与既有回归，不运行 MySQL 目录 |
| `contracts-mysql` | 独立临时 MySQL 8 的真实测试 |
| `contracts-browser` | 现有 Playwright Chromium 测试，2 workers、0 retries，保留失败截图、trace、视频和 HTML 报告 |

Windows 原生窗口、WebView2、图标与关窗进程清理需要 GUI 验收；`windows-desktop` 只验证包内后端。macOS 只验证 runner 架构；Electron、Android 与多架构镜像尚未纳入。

两条工作流均为只读仓库权限，Action 固定提交 SHA，检查有超时且无自动业务重试。npm/pip 只缓存依赖下载。候选包、清单及诊断报告保留 7 天；清单记录原始包 SHA-256、提交、版本和实际 OS/架构。Windows 构建候选名含 `unverified`，需结合后续 `runtime-*` 报告判断。临时数据库、HTTP 重启凭据及生成的密钥不上传。

服务端验证在一次性 GitHub runner 中执行，使用随机 Compose 项目、独立卷与临时凭据，退出时清理资源。流程不发布 Release、不推送镜像、不部署生产，也不执行生产迁移。

[部署包说明](09_Windows与Android部署.md#8-ci-候选包)列出对应打包入口。
