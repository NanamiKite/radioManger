# 设计驱动测试与验收

## 测试原则

测试以 `02`～`10` 设计文档的行为约定为预期。先确定测试矩阵，再实现和运行测试；设计澄清先写入文档，再同步断言。

后端测试保留真实路由、认证、校验、中间件、服务和数据库，只把数据库连接指向测试库；外部 QRZ 在 HTTP 客户端边界模拟，UDP/Telnet 使用 loopback 服务。前端测试使用真实 Vue 页面和浏览器，接口响应在网络边界固定。

断言按状态码和字段精确校验，正常、拒绝、边界和生命周期场景分别验证；不使用 `xfail`、吞异常或放宽断言的方式通过。设计变更需记录原因，并保留首轮断言与失败证据。

## 歧义处理

1. `02` 的“30 天内缓存”和“7 天内恢复”未约定截止时刻的比较符号，测试用可控时钟分别验证期限内与期限后。
2. 首轮按通用业务失败预期为 400 的“无法补全创建关联”和“过期恢复”，经确认后统一为 422；批量呼号查询超过 50 个整体拒绝；UDP 越界输入在失焦时修正到边界。`03`～`05` 已同步这些约定。
3. MySQL 逻辑权限分支在隔离数据库中运行，方言、连接池和迁移可靠性由真实 MySQL 用例验证。

首轮所有新增文件完成后统一运行一次，只修正测试本身的语法、隔离或驱动错误。业务修复按确认后的计划实施，先明确设计再改实现与断言，定向执行受影响路径；首轮结果和修复后的定向结果分别记录。

## 运行命令

后端使用 Python 3.12 和 `backend/requirements.txt` 中固定的依赖。普通 API、WebSocket 和子进程用例使用内存或临时 SQLite：

```bash
cd backend
PYTHONPATH=. python -m pytest tests --ignore=tests/contracts/mysql -q
```

真实 MySQL 用例使用 loopback 上的临时实例，仅接受没有数据库路径的管理员 URL；每个用例创建随机 `radio_contract_<UUID>` 数据库，结束后删除。

```bash
# 先自行启动一次性的 MySQL 8 实例，并绑定到 127.0.0.1 的临时端口。
cd backend
RADIO_TEST_MYSQL_ADMIN_URL='mysql+pymysql://root:<测试密码>@127.0.0.1:<临时端口>' \
  PYTHONPATH=. python -m pytest tests/contracts/mysql -q
```

未提供该 URL 时 MySQL 测试报错。要在同一轮运行全部后端测试，提供相同环境变量并执行 `python -m pytest tests -q`。

浏览器测试使用独立依赖目录，通过登录表单建立会话，HTTP/WebSocket 在网络边界返回固定响应。默认启动独立 Vite 5179 端口，无重试，失败保留截图、trace 与视频：

```bash
npm --prefix frontend ci
npm --prefix frontend/tests ci
cd frontend/tests
npx playwright install chromium
npm test -- --workers=2
```

浏览器 HTML 报告位于 `frontend/tests/playwright-report/`，失败附件位于 `frontend/tests/test-results/`，均不进入版本控制。数据库迁移、代理和真实后端流程由后端/部署测试覆盖。

## 验证边界

- SQLite 与 MySQL 的真实存储验证分别报告；权限逻辑的模式参数不算 MySQL 方言验证。
- Windows/macOS 原生包、Android APK、云上 TLS 与公网 DX 节点不在本轮运行条件内。
- 数据同步与邮件服务目前仅保留接口骨架，暂未接入真实传输（TODO）。
- 百分比按固定样本计算，允许最多 0.05 个百分点的显示舍入误差。
- `band_worked` 是否包含已确认实体未在设计中定义，本轮只按 LoTW 验证已确认实体。

### 测试驱动修正

1. MySQL 观察连接处于 `REPEATABLE READ` 旧快照，`expire_all()` 看不到另一条 HTTP 连接提交的数据。观察前改为结束只读事务 `rollback()`，字段值和会话删除断言不变；独立重跑 MySQL 组，5 项全部通过。
2. UDP 设置用例的选择器同时匹配“登录成功”和“设置保存成功”。改为只定位包含 `Settings saved` 的成功提示，端口请求体、认证头和成功语义断言不变；单独重跑该用例通过。
3. 单例重跑的第一次命令使用带首尾锚点的 grep，没有匹配 Playwright 带文件名前缀的标题，输出 `No tests found`。修正运行命令后用例实际执行并通过。

## 设计澄清与修复

### 实际修复

- `logs.importResult` 的裸 `|` 被 Vue I18n 当作复数分支分隔符；中英文语言包改为字面量 `{'|'}`，完整显示已导入、重复、QSL 更新和错误计数。
- HTTP 错误中间件识别数据库连接失效、连接池超时、SQLite 不可用错误及 MySQL 连接错误，返回 503 和固定的 `Database unavailable` 响应。服务端保留异常日志，客户端不收到 SQL、连接参数或堆栈。约束错误、SQL 编程错误和缺表仍为 500。

### 设计澄清

- 批量呼号查询单次最多 50 个，51 个返回 422 且不查询；不截断、不开放更大批次，也不新增前端批量入口。50 个正常查询和 51 个拒绝的测试分别保留。
- 无可用关联且不能从激活位置补全时创建日志返回 422；过期恢复同为 422。两者仍验证可读错误和无数据变更。
- UDP 采用整数控件的失焦边界修正：1023→1024、65536→65535；显示值与请求一致。空值与相同端口不得启动；后端直接接收非法端口仍为 422。

这些决定先写入 `03`～`05`，再同步断言。

### 修复后的定向验收

后端使用 Python 3.12.16 和 `backend/requirements.txt` 固定依赖，在隔离 SQLite 上运行 HTTP、批量呼号边界、日志关联、回收站、无效令牌、登出、UDP 参数拒绝及导入回归；120 项全部通过。数据库故障用例在 SQL 执行边界注入驱动异常，验证 503/500 分类、固定且不泄露内部信息的响应、无自动重试，以及故障解除后的正常认证。MySQL 错误码属于分类测试，本轮没有重新运行真实 MySQL。

## GitHub Actions

### 日常 PR 检查

[`ci.yml`](../.github/workflows/ci.yml) 只在目标分支为 `main` 的 PR 上运行，不同时监听开发分支 push 或合并后的 push。同一 PR 更新会取消旧运行。范围按合并基线计算；删除和跨目录重命名同时覆盖原、新路径。

| 改动范围 | 自动检查 |
| --- | --- |
| 仅 Markdown 或 `doc/` | 只生成范围与汇总，不安装运行依赖或启动数据库 |
| 前端源码、资源、依赖 | `npm ci`、类型检查、Vite 构建 |
| 后端应用、迁移、依赖 | 既有 SQLite 回归 `tests/test_*.py`，以及独立真实 MySQL 测试 |
| 本地发布入口、桌面启动器 | 既有 SQLite 回归，不启动 MySQL |
| MySQL 专用测试 | 仅真实 MySQL 测试；共享测试 fixture 改动同时覆盖两种模式 |
| 打包脚本、代理或 Compose 配置 | 脚本语法、Compose 配置；打包脚本另核对版本，不构建原生包 |
| 工作流或 `scripts/ci/` | 语法、固定版本 actionlint、版本元数据 |

SQLite 与 MySQL 是独立 job。修改共享后端时同时验证服务器模式；不适用的任务在汇总中标记。未知运行配置采用保守范围。

分支保护可只要求稳定名称 **`CI`**；仓库设置需维护者在首次运行后配置。

### 手动目标验证

在 Actions 的 **Manual target validation → Run workflow** 选择分支与一个 `target`：

| target | 实际执行 |
| --- | --- |
| `web` | 类型检查与静态构建，保存 `dist` |
| `server` | 构建实际镜像，启动隔离 MySQL/FastAPI/Nginx；验证 SPA、资源、认证、QSO、ADI 导出、WebSocket 保存及重启后数据 |
| `windows-web` / `windows-desktop` | Linux 交叉打包，再在 Windows runner 用包内 Python 验证 SQLite、真实 HTTP 流程、密钥和数据持久化 |
| `macos` | 在 `macos-14` 构建，解压到临时目录，走实际 `start.sh` 的虚拟环境安装、启动和重启流程 |
| `contracts-sqlite` | 全部 SQLite/HTTP/实时/子进程测试与既有回归，不运行 MySQL 目录 |
| `contracts-mysql` | 独立临时 MySQL 8 的真实测试 |
| `contracts-browser` | 现有 Playwright Chromium 测试，2 workers、0 retries，保留失败截图、trace、视频和 HTML 报告 |

完整测试保留为手动诊断。修复后的定向结果与首轮历史结果见上文；是否推广为自动门槛需依据整套验收。

Windows 原生窗口、WebView2、图标与关窗进程清理仍需 GUI 验收；`windows-desktop` 只验证包内后端。macOS 只验证实际 runner 的架构；Electron、Android 与多架构镜像尚未纳入该流程。

两条工作流均为只读仓库权限，Action 固定提交 SHA，检查有超时且无自动业务重试。npm/pip 只缓存依赖下载。候选包、清单及诊断报告保留 7 天；清单记录原始包 SHA-256、提交、版本和实际 OS/架构。Windows 构建候选名含 `unverified`，需结合后续 `runtime-*` 报告判断。临时数据库、HTTP 重启凭据及生成的密钥不上传。

服务端验证在一次性 GitHub runner 中执行，使用随机 Compose 项目、独立卷与临时凭据，退出时清理资源。流程不发布 Release、不推送镜像、不部署生产，也不执行生产迁移。

[部署包说明](09_Windows与Android部署.md#8-ci-候选包)列出对应打包入口。
