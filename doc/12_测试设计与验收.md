# 设计驱动测试与验收

## 原则

本测试设计以 `02`～`10` 设计文档的行为契约为预期，不以当前业务实现或现有测试结果为预期。先确定下表，再实现、运行测试。只新增测试和测试环境配置，不修改业务源码或设计要求。

- 明确的状态码精确断言，不使用“任意 4xx 都算通过”。
- 正常、拒绝、上下界、生命周期分别验证；拒绝请求后还要验证数据未被修改。
- 没有 `xfail`、吞异常后通过、根据实际返回值选择断言或为已知实现绕过边界。
- 数据库使用隔离 SQLite 和临时目录；真实 MySQL、平台打包和代理链验证另列，不把模式分支模拟称作 MySQL 验证。
- HTTP 测试保留真实路由、认证、校验、中间件、服务与数据库；只替换数据库连接到测试库。不以测试用户替换认证依赖。
- 外部 QRZ 故障可在 HTTP 客户端边界模拟，不能替换呼号服务本身。UDP/Telnet 使用 loopback 服务。
- 前端组件流程使用真实页面和浏览器，接口响应在网络边界固定；这证明前端契约，不代替真实前后端端到端验证。
- 不修改既有用例。失败保留原始断言、HTTP 响应和数据库状态，并报告为契约差异或环境问题。

## 歧义处理

1. `02` 的“30 天内缓存”和“7 天内恢复”未约定恰好截止时刻的比较符号：用可控时钟验证期限内与期限后，不凭源码选择截止等号语义。
2. `04` 说明没有激活位置时创建日志为业务失败，但未单独给出状态码；按 `03` 的业务条件不满足使用 400。若设计另有决定，必须先明确修改契约，不能在跑出结果后改成任意 4xx。
3. MySQL 逻辑权限分支可在隔离数据库中运行，但不证明 MySQL 方言、连接池或迁移可靠性；需要实际 MySQL 的部分不得报告为已通过。
4. 邮件与 GitHub 同步明确为预留，不设计“真实发送成功/备份完成”测试，不用成功回显证明数据已上传。

所有新增文件完成后统一运行一次；不根据运行结果修改业务或降低验收标准。可修正测试本身的语法、隔离或驱动错误，但须说明原因，不能改变预期行为。结果保留为终端输出和测试报告，明确通过、失败、未执行与环境阻塞。

## 运行命令

后端使用 Python 3.12 和 `backend/requirements.txt` 中固定的依赖。普通 API、WebSocket 和子进程用例使用内存或临时 SQLite，不读取应用实际数据库：

```bash
cd backend
PYTHONPATH=. python -m pytest tests --ignore=tests/contracts/mysql -q
```

真实 MySQL 用例是显式集成测试。仅接受 loopback 上没有数据库路径的管理员 URL；每个用例创建随机 `radio_contract_<UUID>` 数据库，结束后删除。不要把生产服务器凭据传给测试。

```bash
# 先自行启动一次性的 MySQL 8 实例，并绑定到 127.0.0.1 的临时端口。
cd backend
RADIO_TEST_MYSQL_ADMIN_URL='mysql+pymysql://root:<测试密码>@127.0.0.1:<临时端口>' \
  PYTHONPATH=. python -m pytest tests/contracts/mysql -q
```

未提供该 URL 时 MySQL 测试明确报错，不自动跳过。要在同一轮运行全部后端测试，提供相同环境变量并执行 `python -m pytest tests -q`。

浏览器测试使用独立依赖目录，不修改应用依赖。真实 Vue 页面通过登录表单建立会话，HTTP/WebSocket 在网络边界接收固定响应。默认启动独立 Vite 5179 端口，无重试，失败保留截图、trace 与视频：

```bash
npm --prefix frontend ci
npm --prefix frontend/tests ci
cd frontend/tests
npx playwright install chromium
npm test -- --workers=2
```

浏览器 HTML 报告位于 `frontend/tests/playwright-report/`，失败附件位于 `frontend/tests/test-results/`；它们不进入版本控制。数据库迁移、代理与真实后端功能仍由后端/部署测试验证，浏览器网络边界测试不能代替它们。

## 验证边界

- SQLite 与 MySQL 的真实存储验证分别报告，权限逻辑模式参数不算 MySQL 方言验证。
- Windows/macOS 原生包、Android APK、云上 TLS 与公网 DX 节点未作为本轮运行条件，不能据此声称已经验证。
- 邮件发送和 GitHub 文件同步仍是预留功能；本轮不把接口回显当作功能完成。
- 百分比的数量严格验证；比例由固定样本数学计算，允许最多 0.05 个百分点的显示舍入误差，不固定文档未指定的小数位数。
- `band_worked` 的含义未在设计中说明是否包含已确认实体；本轮不据源码替它定义语义，已确认实体仍严格按 LoTW 验证。

### 仅修正测试驱动的问题

1. MySQL 测试观察连接仍处于 `REPEATABLE READ` 旧快照中，不能用 `expire_all()` 看见另一条 HTTP 连接提交的数据。观察前改为结束只读事务 `rollback()`，保持字段值和会话删除断言不变；独立重跑 MySQL 组，5 项全部通过。
2. UDP 设置保存的浏览器用例选择器同时匹配“登录成功”和“设置保存成功”。改成只定位包含 `Settings saved` 的成功提示，端口请求体、认证头和成功语义断言不变；单独重跑该用例通过。
3. 单例重跑的第一次命令使用带首尾锚点的 grep，没有匹配 Playwright 带文件名前缀的标题，输出 `No tests found`。修正运行命令后该用例实际执行并通过；没有把“未找到测试”当作通过。
