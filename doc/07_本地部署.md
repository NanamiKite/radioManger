# 本地部署

## 部署模式对比

| 方式 | 网页入口 | 数据库与后端 | 适用条件 |
| --- | --- | --- | --- |
| 源码本地运行 | Vite，默认 5173 | 本机 FastAPI 8000 + SQLite | 已安装 Python、Node.js |
| Docker 服务器 | Nginx 80 | FastAPI + MySQL + Redis | 多用户、局域网或云服务器 |
| Windows Web 本地包 | 浏览器访问 8000 | 包内 Python + SQLite | 使用打包后的 `start.bat` |
| Windows pywebview 包 | WebView2 窗口访问本机 8000 | 后端子进程 + SQLite | 需要 pywebview 依赖及 WebView2 |
| Electron | 加载前端页面 | Python 后端需另行提供 | 仓库仅配置前端壳打包 |
| Android 浏览器/容器 | 服务器网页或 Capacitor 资源 | 远程后端 | 需要可访问的服务器；容器还需配置 API 路由 |

后端模式通过配置选择，不能在前端设置页切换。部署命令从项目根目录开始说明；命令中的密码、密钥、绝对路径和域名需要替换为部署值。服务器与 Windows、Android 部署分别见[服务器部署](08_服务器部署.md)与 [Windows 与 Android 部署](09_Windows与Android部署.md)。

## 1. 纯本地部署

### 1.1 前置要求

源码环境可按仓库容器和打包脚本使用 Python 3.12、Node.js 22，以及 npm。初次安装依赖需要网络；日志数据库读写在本机完成。QRZ、DX Cluster 和在线地图底图仍需要网络。

### 1.2 配置与脚本启动

先创建 `backend/.env`。已有配置时编辑原文件，保留数据库路径与 JWT 密钥。

```dotenv
DATABASE_MODE=sqlite
SQLITE_URL=sqlite:////absolute/path/radioManger/backend/radiomanager.db
SQLITE_PATH=/absolute/path/radioManger/backend/radiomanager.db
SECRET_KEY=replace-with-a-random-secret
ENVIRONMENT=development
DEBUG=true
ENABLE_TEST_ACCOUNT=false
CORS_ORIGINS=["http://localhost:5173"]
```

Unix SQLite 绝对路径在 `sqlite:` 后有四个 `/`。Windows 示例为 `SQLITE_URL=sqlite:///C:/RadioManager/backend/radiomanager.db`、`SQLITE_PATH=C:/RadioManager/backend/radiomanager.db`。路径中的目录须已存在；两个变量应指向同一个文件。

从 Python 生成密钥后填入 `.env`：

```bash
python3 -c 'import secrets; print(secrets.token_hex(32))'
```

配置完成后，在项目根目录运行：

```bash
./start-local.sh
```

该脚本创建或激活 `backend/venv`、初始化数据库，再启动 FastAPI 和 Vite。首次创建虚拟环境时安装后端依赖，缺少前端依赖目录时运行 npm 安装。脚本读取现有配置，不会强制覆盖 `DATABASE_MODE`，也没有实现 `--build` 参数。

### 1.3 手动启动

后端终端：

```bash
cd backend
python3 -m venv venv
source venv/bin/activate
python -m pip install -r requirements.txt
python -m app.scripts.init_db
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

前端终端：

```bash
cd frontend
npm ci
npm run dev
```

使用绝对 SQLite 路径可让初始化和运行进程始终使用同一个文件。日后启动后端时，也应从 `backend/` 运行，以读取同一 `.env`。

### 1.4 访问

- 网页：[http://localhost:5173](http://localhost:5173)
- 健康检查：[http://localhost:8000/health](http://localhost:8000/health)
- 交互 API 文档：[http://localhost:8000/docs](http://localhost:8000/docs)，仅 `DEBUG=true` 时开放

默认不创建测试账号，在注册页创建账户即可。登录后先创建台站和位置；第一个位置会自动激活。

## 环境变量配置

[`config.py`](../backend/app/config.py) 从进程环境和当前工作目录的 `.env` 读取设置，环境变量优先，变量名区分大小写。下表覆盖两种数据库模式的全部常用变量。

| 变量 | 默认值或用途 |
| --- | --- |
| `DATABASE_MODE` | `sqlite`；服务器用 `mysql` |
| `SQLITE_URL` | 默认 `sqlite:///./radiomanager.db`；实际数据库连接 |
| `SQLITE_PATH` | 默认 `./radiomanager.db`；设置页显示路径 |
| `DATABASE_URL` | MySQL 必填，如 `mysql+pymysql://用户:密码@主机:3306/数据库` |
| `SECRET_KEY` | 生产环境必须非空，使用持久随机值 |
| `ENVIRONMENT` | 默认 `production` |
| `DEBUG` | 默认 `false`，控制 `/docs` 与 `/redoc` |
| `CORS_ORIGINS` | JSON 数组，如 `["https://radio.example.com"]` |
| `REDIS_URL` | 默认 `redis://localhost:6379` |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | 默认 10080，即 7 天 |
| `REFRESH_TOKEN_EXPIRE_DAYS` | 默认 30；没有刷新端点 |
| `ADMIN_USERNAME/PASSWORD/EMAIL` | MySQL 显式初始化时使用；密码为空则跳过创建 |
| `ENABLE_TEST_ACCOUNT` | 默认 `false`；仅控制 SQLite 初始化脚本的测试账户创建 |
| `TEST_ACCOUNT_USERNAME/PASSWORD/EMAIL` | SQLite 测试账户及发布入口使用的账户配置 |
| `QRZ_USERNAME/PASSWORD` | QRZ XML 查询凭据 |
| `UDP_WSJTX_PORT/UDP_N1MM_PORT` | 默认 2237 / 12060 |
| `UDP_ENABLED` | 已定义，但不触发自动监听 |
| `GITHUB_TOKEN`、`SMTP_*` | 同步与邮件的预留配置，不表示功能已经接通 |

`backend/.env.example` 可用于查找配置项，其中的示例凭据需要替换；`CORS_ORIGINS` 应使用 JSON 数组，不能用逗号分隔字符串。导入路由实际限制 50 MiB，不使用配置中的 `MAX_UPLOAD_SIZE` 值。
