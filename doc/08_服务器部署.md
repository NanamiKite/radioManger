# 服务器部署

适用于多人访问的局域网与云服务器场景。单机使用见[本地部署](07_本地部署.md)；环境变量含义见[环境变量配置](07_本地部署.md#环境变量配置)。

## 1. 局域网部署

### 1.1 Docker 全栈部署

[`docker-compose.yml`](../docker-compose.yml) 启动 MySQL、Redis、FastAPI 和前端 Nginx。Compose 的变量替换读取**项目根目录 `.env`**，它与源码后端使用的 `backend/.env` 是不同文件。

在根目录 `.env` 填入以下变量，替换所有占位值。数据库密码会进入连接 URL，使用不含 URL 保留字符的随机值，或正确编码。

```dotenv
MYSQL_ROOT_PASSWORD=replace-with-a-random-root-password
MYSQL_PASSWORD=replace-with-a-random-db-password
SECRET_KEY=replace-with-a-random-jwt-secret
ADMIN_USERNAME=admin
ADMIN_PASSWORD=replace-with-a-random-admin-password
ADMIN_EMAIL=admin@example.com
```

前端依赖 `/health` 识别服务器模式。构建前，在 [`frontend/nginx.conf`](../frontend/nginx.conf) 的 `server` 块内补充健康检查转发：

```nginx
location = /health {
    proxy_pass http://backend:8000;
    proxy_set_header Host $host;
}
```

现有配置已包含 `/api`、DX Cluster/UDP WebSocket 和 SPA 回退。Nginx 的上传大小限制需要与导入需求一致；如需允许最大 50 MiB 文件及 multipart 开销，可在该 `server` 块设置 `client_max_body_size 51m;`。默认 Nginx 限制可能先于 API 拒绝文件。

配置好后，在项目根目录运行：

```bash
docker compose up -d --build
docker compose exec backend python -m app.scripts.init_db
docker compose ps
curl http://localhost:8000/health
```

后端镜像启动命令直接运行 Uvicorn，不执行管理员初始化；首次部署的第二条命令不可省略。已有同用户名账户时，初始化不会覆盖其密码。

浏览器访问 `http://服务器IP/`，使用配置的管理员登录。MySQL 与 Redis 数据分别存入 `mysql_data`、`redis_data` 卷。停止服务使用 `docker compose down`；需保留数据时不要添加 `-v`。

仓库 Compose 同时发布 80、8000、3306、6379 端口。普通浏览器只需要前端入口；部署方应按网络范围限制数据库、Redis 和后端端口，或调整端口映射。

### 1.2 前后端分机部署

客户端依赖同源 `/api/v1`、`/health` 和 WebSocket 路径。只设置 CORS 或启动脚本中的 API 地址变量，不会更改请求目标。

开发时，在前端机器的 `vite.config.ts` 中把 `/api` 和 `/health` 的 `target` 都改为实际后端地址，保留 `/api` 的 `ws:true`，再运行：

```bash
cd frontend
npm ci
npm run dev -- --host 0.0.0.0
```

后端监听允许其他机器访问的地址：

```bash
cd backend
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 1
```

正式部署时，构建 `frontend/dist` 并由 Nginx 托管，通过同源代理转发三类路径。Vite 开发服务器只用于开发环境。

### 1.3 数据库选择

SQLite 使用本机文件，适合个人日志；MySQL 使用独立数据库服务，并启用服务器管理接口。SQLite 模式仍有用户认证，不代表无账号、无权限隔离。

数据库模式切换只改变连接目标，不迁移旧数据。迁移前应备份数据库；ADI 导入导出只覆盖部分字段，不能作为完整迁移方式。

## 2. 服务器部署模式（MySQL + Redis）

非容器运行时，在 `backend/.env` 设置：

```dotenv
DATABASE_MODE=mysql
DATABASE_URL=mysql+pymysql://radiomanager:replace-password@127.0.0.1:3306/radiomanager
REDIS_URL=redis://127.0.0.1:6379/0
SECRET_KEY=replace-with-a-random-secret
ADMIN_USERNAME=admin
ADMIN_PASSWORD=replace-with-a-random-admin-password
ADMIN_EMAIL=admin@example.com
ENVIRONMENT=production
DEBUG=false
ENABLE_TEST_ACCOUNT=false
CORS_ORIGINS=["https://radio.example.com"]
```

先创建 MySQL 数据库及应用用户并授予该库权限，再从 `backend/` 执行初始化。数据库创建可使用 `utf8mb4` 字符集。根目录 `init-db.sh` 使用固定示例凭据，不应直接用于正式凭据管理。

MySQL 模式启用管理员路由、登录会话、操作审计和令牌黑名单。Redis 初始化不可用时，黑名单回退进程内存；重启或不同 worker 之间无法保留这种撤销状态。后端默认未提供多进程共享的 DX Cluster/UDP 管理器，应使用单 worker。

## 3. 云服务器部署

### 3.1 运行结构

云部署复用服务器模式，域名和 TLS 由入口代理提供。可以在已启动的 Compose 前端之外配置 TLS 网关，或直接由宿主机 Nginx 托管静态构建。对外网页和 API 保持同源。

### 3.2 静态前端与反向代理

构建前端：

```bash
cd frontend
npm ci
npm run build
```

将 `dist/` 部署到静态目录，例如 `/var/www/radiomanager`。下面的配置假定后端运行在同一主机的 `127.0.0.1:8000`；证书和目录由部署方准备：

```nginx
server {
    listen 80;
    server_name radio.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name radio.example.com;
    ssl_certificate /etc/ssl/radiomanager/fullchain.pem;
    ssl_certificate_key /etc/ssl/radiomanager/privkey.pem;

    root /var/www/radiomanager;
    index index.html;
    client_max_body_size 51m;

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 180s;
    }

    location = /health {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
    }

    location ~ ^/api/v1/(dxcluster|udp)/ws$ {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 86400s;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

域名使用 HTTPS 后，前端自动使用 `wss` 连接 WebSocket。代理访问日志不宜记录含 token 的 WebSocket 查询参数。

仓库根目录的 `nginx.conf` 是另一种入口示例：它把网页代理到 5173，而不是直接托管 `dist/`；同样需要补充 `/health`。不要在同一个部署中混淆开发服务器代理与静态资源托管方式。

### 3.3 运行维护

通过进程管理器或容器保持后端运行，从固定工作目录读取 `.env`。升级前保存数据库、配置与旧版本产物，在副本验证升级，再更新服务。`create_all` 不会升级已有列结构。

健康检查必须读取 JSON 中的 `status` 和 `subsystems`。API 在数据库或 Redis 异常时仍返回 HTTP 200，容器现有健康检查只检查 HTTP 可达，不保证子系统正常。初始化与备份步骤见[初始化备份与常见问题](10_初始化备份与常见问题.md)。
