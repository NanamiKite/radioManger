# 数据库设计说明

## 概述

RadioManager 用 SQLAlchemy 定义一套业务模型，由 `DATABASE_MODE` 选择 SQLite 或 MySQL。模型定义位于 [`backend/app/models/`](../backend/app/models/)，引擎配置位于 [`database/base.py`](../backend/app/database/base.py)。本文的字段名均为实际数据库列名。

| 模式 | 连接配置 | 连接行为 |
| --- | --- | --- |
| `sqlite`，默认 | `SQLITE_URL` | `check_same_thread=False`，每次连接启用 WAL 和外键检查 |
| `mysql` | `DATABASE_URL` | `pool_pre_ping=True`，`pool_recycle=3600` |

`SQLITE_PATH` 只用于报告数据库文件位置，不参与引擎连接。相对路径以进程工作目录为基准；部署时应让 `SQLITE_URL` 和 `SQLITE_PATH` 指向同一个绝对路径。

## 数据库架构

### 数据表

应用注册 12 张业务表。Alembic 另使用 `alembic_version` 记录迁移版本，该表不属于业务模型。

| 表 | 模型 | 用途 |
| --- | --- | --- |
| `users` | `User` | 用户、权限和偏好 |
| `stations` | `Station` | 台站呼号 |
| `locations` | `Location` | 操作位置、设备与激活状态 |
| `qso_logs` | `QSOLog` | 通联日志 |
| `callsign_cache` | `CallsignCache` | 共享的呼号查询缓存 |
| `statistics` | `Statistics` | 用户统计快照 |
| `log_files` | `LogFile` | 导入文件元数据 |
| `sync_history` | `SyncHistory` | 同步历史 |
| `deleted_logs` | `DeletedLog` | 回收站日志快照 |
| `audit_logs` | `AuditLog` | 操作审计 |
| `user_sessions` | `UserSession` | 登录会话和活跃时间 |
| `system_configs` | `SystemConfig` | 管理后台配置项 |

### 表设计原则

业务表主键均为整数 `id`。用户业务数据通过 `user_id` 关联；呼号缓存没有 `user_id`，由所有用户共用。时间列通常使用去除时区信息的 UTC 值，QSO 日期和时间分别保存。

`default` 和 `onupdate` 多为 SQLAlchemy 应用侧默认值，不等同于数据库 `DEFAULT` 或触发器。各表的时间列、软删除列和外键策略并不相同，以下分别说明。

### 1. users（用户表）

来源：[`user.py`](../backend/app/models/user.py)。

| 字段 | 类型与约束 | 含义 |
| --- | --- | --- |
| `username` | `String(50)`，必填、唯一、有索引 | 登录名 |
| `email` | `String(100)`，必填、唯一、有索引 | 邮箱 |
| `password_hash` | `String(255)`，必填 | bcrypt 密码哈希 |
| `full_name` / `avatar_url` | `String(100)` / `String(500)` | 显示姓名、头像地址 |
| `role` | `String(20)`，默认 `user` | `user` 或 `admin` |
| `timezone` / `language` | `String(50)` / `String(10)` | 默认 `UTC`、`zh-CN` |
| `is_active` / `is_deleted` | `Boolean` | 默认 `True`、`False` |
| `deletion_scheduled_at` | `DateTime`，可空 | 账号注销申请时间 |
| `deletion_cancelled` | `Boolean`，默认 `False` | 注销状态字段 |
| `created_at` / `updated_at` | `DateTime` | 创建、更新时间；创建时间有索引 |

账号禁用与软删除不会物理删除用户数据。用户名、邮箱的唯一约束仍覆盖软删除记录。

### 2. stations（台站表）

来源：[`station.py`](../backend/app/models/station.py)。

| 字段 | 类型与约束 | 含义 |
| --- | --- | --- |
| `user_id` | `Integer`，必填、外键、有索引 | 所属用户 |
| `callsign` | `String(20)`，必填、有索引 | 台站呼号，服务层去空格并转大写 |
| `is_deleted` | `Boolean`，默认 `False` | 软删除标记 |
| `created_at` / `updated_at` | `DateTime` | 创建、更新时间 |

唯一索引 `idx_user_callsign` 覆盖 `(user_id, callsign, is_deleted)`。创建同呼号台站时，服务优先恢复已有的软删除台站。台站不保存网格、电台或天线信息。

### 3. locations（位置表）

来源：[`location.py`](../backend/app/models/location.py)。

| 字段 | 类型与约束 | 含义 |
| --- | --- | --- |
| `user_id` / `station_id` | `Integer`，必填、外键、有索引 | 所属用户、台站 |
| `name` | `String(100)`，必填 | 位置名称 |
| `grid_square` | `String(6)`，必填 | 本台梅登网格 |
| `radio_model` / `antenna_model` | `String(100)` | 电台、天线型号 |
| `antenna_height` | `Numeric(5,2)` | 天线高度，米 |
| `qth` | `String(200)` | 位置描述 |
| `is_active` / `is_deleted` | `Boolean`，默认均为 `False` | 激活、软删除状态 |
| `created_at` / `updated_at` | `DateTime` | 创建、更新时间 |

同一用户只激活一个位置的规则由 `LocationService` 执行：先取消该用户全部位置的激活状态，再激活目标。数据库没有为该规则建唯一约束。首个未删除位置自动激活。

### 4. qso_logs（通联日志表）

来源：[`qso_log.py`](../backend/app/models/qso_log.py)。除 `id`、`user_id`、`station_id`、`call_sign`、`qso_date` 外，其余列在模型中均可空。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `user_id` / `station_id` | `Integer` | 用户、台站外键 |
| `location_id` | `Integer` | 操作位置外键，可空 |
| `call_sign` | `String(20)` | 对方呼号 |
| `qso_date` / `qso_date_off` | `Date` | 开始、结束日期 |
| `time_on` / `time_off` | `Time` | 开始、结束时间，按 UTC 使用 |
| `freq` / `freq_rx` | `Numeric(10,6)` | 发射、接收频率，MHz |
| `band` / `band_rx` | `String(10)` | 发射、接收波段 |
| `mode` | `String(20)` | 通联模式 |
| `rst_sent` / `rst_rcvd` | `String(5)` | 发出、收到的信号报告 |
| `grid_square` | `String(6)` | 对方梅登网格 |
| `operator` / `qth` | `String(50)` / `String(200)` | 操作员、对方位置描述 |
| `qsl_sent` / `qsl_rcvd` | `String(1)`，默认 `N` | 纸质 QSL 状态 |
| `eqsl_sent` / `eqsl_rcvd` | `String(1)`，默认 `N` | eQSL 状态 |
| `lotw_sent` / `lotw_rcvd` | `String(1)`，默认 `N` | LoTW 状态 |
| `distance` | `Integer` | 距离，千米 |
| `dxcc` | `String(100)` | DXCC 实体名称 |
| `tx_pwr` | `Integer` | 发射功率，瓦 |
| `my_gridsquare` | `String(6)` | 本台网格 |
| `station_callsign` / `my_call` | `String(20)` | 台站、操作员呼号字段 |
| `prop_mode` / `sat_name` | `String(20)` / `String(50)` | 传播模式、卫星名称 |
| `srx` / `stx` | `String(20)` | 接收、发送序列号 |
| `contest_id` | `String(50)` | 比赛标识 |
| `comment` | `Text` | 备注 |
| `is_deleted` | `Boolean`，默认 `False` | 软删除标记 |
| `created_at` / `updated_at` | `DateTime` | 创建、更新时间 |

创建、导入和响应 Schema 包含 `my_call`、传播、卫星和比赛字段；普通 PATCH 只支持其声明的更新字段。该表只覆盖应用使用的 ADIF 字段。台站、位置写入前必须验证用户归属，位置所属台站必须与日志一致。

创建日志时，未指定台站则使用当前用户的激活位置；未指定日期或开始时间则填入 UTC 当前值。缺少 `dxcc` 时按呼号推断。创建及导入新记录时，`qsl_rcvd="Y"` 会把纸质、LoTW 和 eQSL 的其余状态均置为 `Y`；普通 PATCH 不执行这段联动。

### 5. callsign_cache（呼号查询缓存表）

来源：[`callsign_cache.py`](../backend/app/models/callsign_cache.py)。

| 字段 | 类型与含义 |
| --- | --- |
| `call_sign` | `String(20)`，必填、唯一、有索引 |
| `first_name` / `last_name` / `full_name` | `String(100)` / `String(100)` / `String(200)` |
| `country` / `grid_square` | `String(100)`，有索引 / `String(6)` |
| `latitude` / `longitude` | `Numeric(10,6)` / `Numeric(11,6)` |
| `class_type` | `String(50)`，执照等级 |
| `license_date` / `license_exp` | `Date`，执照日期 |
| `previous_call` | `String(20)`，原呼号 |
| `cached_at` | `DateTime`，缓存时间，有索引 |
| `qrz_url` | `String(500)`，QRZ 页面 |

30 天内的缓存直接返回；过期后尝试在线刷新，失败仍可返回旧缓存。缓存没有自动到期删除任务。

### 6. statistics（统计数据表）

来源：[`statistics.py`](../backend/app/models/statistics.py)。

`user_id` 为用户外键，通过 `idx_user_id_unique` 保证每用户最多一行。整数计数字段包括 `total_qso`、`total_dxcc`、`total_waz`、`total_distance`、`qsl_sent`、`qsl_rcvd`、`eqsl_sent`、`eqsl_rcvd`、`lotw_confirmed`，默认均为 0。

`statistic_data` 为 JSON 扩展数据，`calculated_at` 为时间字段。`StatsService.refresh_statistics` 可写入快照，但常用统计 API 直接聚合 `qso_logs`，不依赖该表自动刷新。`total_waz` 尚未完整计算。

### 7. log_files（日志文件追踪表）

来源：[`log_file.py`](../backend/app/models/log_file.py)。

| 字段 | 类型与含义 |
| --- | --- |
| `user_id` | `Integer`，必填用户外键 |
| `file_name` / `file_path` | `String(255)`，必填 / `String(500)` |
| `file_size` / `file_hash` | `Integer` / `String(64)`，大小与哈希预留字段 |
| `format` / `qso_count` | `String(20)` / `Integer`，格式与导入条数 |
| `import_status` | SQLAlchemy `Enum`：`pending`、`success`、`failed`、`partial` |
| `import_error` | `Text`，导入错误 |
| `github_url` / `cloud_url` / `last_sync_at` | `String(500)` / `String(500)` / `DateTime`，同步元数据 |
| `is_deleted` / `created_at` / `updated_at` | 软删除标记与时间 |

`idx_user_hash` 唯一索引覆盖 `(user_id, file_hash)`。现有导入服务保存文件名、内容长度、导入数和结果，不计算 `file_hash`，也不把原文件写到 `file_path`。该表不能替代原文件备份。

### 8. sync_history（同步历史表）

来源：[`sync_history.py`](../backend/app/models/sync_history.py)。

包含用户外键 `user_id`、`sync_type`（`push/pull/merge`）、`source`、`status`（`pending/success/failed`）、`added_count`、`updated_count`、`deleted_count`、`conflict_count`、`error_message`、`created_at`、`completed_at`。

类型和状态使用 SQLAlchemy `Enum`。推送接口会写入历史记录。

### 9. deleted_logs（回收站表）

来源：[`deleted_log.py`](../backend/app/models/deleted_log.py)。

| 字段 | 类型与含义 |
| --- | --- |
| `user_id` | `Integer`，必填用户外键 |
| `log_id` | `Integer`，原日志 ID；没有外键约束 |
| `log_data` | `JSON`，必填日志快照 |
| `delete_reason` | `String(500)` |
| `deleted_at` / `expires_at` | `DateTime`，删除时间及 7 天后的到期时间 |
| `is_restored` | `Boolean`，默认 `False` |

列表只显示未恢复、未过期条目。恢复优先把原 `qso_logs` 记录的 `is_deleted` 改回 `False`；原记录不存在时才从快照重建。恢复日志不会自动恢复软删除的台站和位置。

列表过滤过期条目；清空和批量删除只删除备份，不物理删除原日志。没有定时清理任务。恢复时验证现有台站和位置的归属及可用性，不自动恢复父记录；原日志缺失时只按通过校验的快照重建。

### 10. audit_logs（审计日志表）

来源：[`audit_log.py`](../backend/app/models/audit_log.py)。

`user_id` 为必填用户外键；`username`、`action` 为必填字符串。`target_type`、`target_id`、`detail`、`ip_address` 记录操作对象和说明，`created_at` 保存 UTC 时间。`user_id`、`action`、`created_at` 有索引。

没有 `updated_at` 或 `is_deleted`。用户外键未声明 `ON DELETE CASCADE`；操作审计不等同于完整的 QSO 内容历史版本。

### 11. user_sessions（用户会话表）

来源：[`user_session.py`](../backend/app/models/user_session.py)。

字段为 `user_id`、`token_jti`、`ip_address`、`user_agent`、`created_at`、`last_active`、`expires_at`。`user_id` 为必填外键，`token_jti` 唯一且有索引。SQLite 和 MySQL 登录均创建会话；HTTP/WebSocket 必须找到对应用户的未过期会话。活跃时间最多每 60 秒写入一次，在线数按近 15 分钟活跃用户去重计算。

会话是令牌撤销的唯一依据：登出删除当前会话，密码变更、禁用和账号删除在同一事务中删除全部会话。不存在 Redis 或内存黑名单降级。

### 12. system_configs（系统配置表）

来源：[`system_config.py`](../backend/app/models/system_config.py)。

字段为 `key`、`value`、`value_type`、`description`、`updated_by`、`updated_at`。`key` 为 `String(100)`，必填、唯一、有索引；`value` 为文本，`updated_by` 为用户外键。

后台首次读取空配置表时初始化默认项。该表与 `Settings` 环境变量是两套配置来源；导入、限流及节点连接当前读取 `Settings`。

## SQLite 兼容说明

SQLite 连接启用 `PRAGMA journal_mode=WAL` 与 `PRAGMA foreign_keys=ON`。MySQL 使用连接池存活检查。`role` 使用字符串；`log_files` 和 `sync_history` 仍使用 SQLAlchemy `Enum`，由方言映射为数据库类型。

Alembic 使用 `render_as_batch=True`。冻结基线 `000000000001` 创建完整表结构，`5eed5637c7eb` 随后调整 `users.role`。空库直接迁移到 head；无版本旧库只能在显式 `--adopt-legacy` 校验结构后接管。迁移失败不会被 stamp 为成功。

## 索引优化

### 关键索引

| 表 | 索引 |
| --- | --- |
| `qso_logs` | `idx_user_date(user_id, qso_date)`；`user_id`、`call_sign`、`qso_date`、`band`、`mode`、`location_id` 的单列索引 |
| `stations` | `idx_user_callsign(user_id, callsign, is_deleted)` 唯一索引 |
| `locations` | `user_id`、`station_id` 单列索引 |
| `statistics` | `idx_user_id_unique(user_id)` 唯一索引 |
| `log_files` | `idx_user_hash(user_id, file_hash)` 唯一索引 |
| `deleted_logs` | `idx_expires_at(expires_at)`，另有用户与删除时间索引 |

导入去重由服务层执行，数据库没有唯一约束。

## 数据一致性

### 事务处理

普通 CRUD 在服务方法内提交。导入每累计 500 条新记录提交一次，数据库批次失败回滚当前批次并返回 503 和已提交计数，不继续使用失败 Session；此前批次仍保留。台站删除中的日志快照、日志软删除、位置及台站软删除在一个事务内完成。

### 级联删除策略

| 关系或操作 | 实际行为 |
| --- | --- |
| 用户 → 台站、位置、QSO、回收站、统计、文件记录、同步历史 | 外键声明 `CASCADE`；只有物理删除才触发 |
| 台站 → QSO | 外键 `RESTRICT`，阻止物理删除仍被日志引用的台站 |
| 台站 → 位置 | 外键 `CASCADE` |
| 位置 → QSO | 外键 `SET NULL`，只在物理删除位置时触发 |
| API 删除台站 | 日志备份及软删除 → 位置软删除 → 台站软删除 |
| API 删除位置 | 仅软删除位置，已有日志的 `location_id` 保留 |
| API 删除日志 | 保存回收站快照并软删除原日志 |

### 台站软删除恢复

同呼号重建只恢复台站记录。需要恢复日志时使用回收站接口；已删除位置需另行处理。日志快照恢复与外键有效性仍受原台站、位置记录的存在状态影响。

## 备份建议

SQLite 开启 WAL 时，运行中仅复制 `.db` 文件可能遗漏 WAL 中的数据。在线备份应使用 SQLite backup API；离线复制前先停止写入并正常关闭连接。MySQL 应使用数据库备份工具。保存数据库时同时保存部署配置，并在副本上检查可恢复性。

操作步骤见[初始化备份与常见问题](10_初始化备份与常见问题.md#1-数据库初始化)。
