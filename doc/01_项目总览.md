# RadioManager — 项目总览

## 项目概述

RadioManager 是业余无线电 QSO 日志管理工具，前端使用 Vue 3，后端使用 FastAPI。日志保存在 SQLite 或 MySQL，通过 ADI/ADIF 文件导入导出。

浏览器、Electron 和 pywebview 窗口共用同一套前后端业务代码。数据库模式由后端的 `DATABASE_MODE` 决定；前端通过 `/health` 识别模式，再显示该模式的管理入口。设置页不负责切换数据库。

## 项目特性

| 功能 | 使用方式与边界 |
| --- | --- |
| 台站与位置 | 台站保存呼号，位置保存网格和设备信息；同一用户通过激活操作选择一个位置 |
| 日志管理 | 新增、编辑、筛选、排序、分页、ADI/ADIF 导入和 ADI 导出 |
| 回收站 | 单条日志删除和台站删除均备份日志，7 天内可恢复 |
| 统计 | QSO 概览、波段与模式分布、DXCC 实体及实体×波段图表 |
| 呼号查询 | 优先使用数据库缓存，再查询 QRZ.com；不可用时回退旧缓存或离线 DXCC 推断 |
| DX Cluster | 后端连接 Telnet 节点，通过 WebSocket 推送 spot |
| 地图 | OpenStreetMap 底图、梅登网格、放射线和灰线图层 |
| 工具箱 | 频率/波长、偶极天线、垂直天线、SWR、LC 滤波器和通用计算 |
| UDP 接收 | 接收 WSJT-X 类数据和 N1MM XML 广播，通过 WebSocket 推送；接收本身不写入日志 |
| 用户与管理 | JWT 登录；MySQL 模式增加用户管理、审计和系统配置页面 |
| 多语言支持 | 中文 `zh-CN`、英文 `en-US` |

自定义快捷链接保存在后端进程内存中，重启后丢失。

## 技术栈

### 前端

Vue 3、TypeScript、Vite、Element Plus、Pinia、Vue Router、Axios 和 vue-i18n。地图使用 Leaflet，太阳位置计算使用 SunCalc。Electron 与 Capacitor 提供客户端配置，Windows 原生窗口另有独立的 pywebview 启动器。

### 后端

FastAPI、Uvicorn、SQLAlchemy 2、Pydantic 2 和 pydantic-settings。密码使用 bcrypt 哈希，JWT 使用 PyJWT。SQLite/MySQL 都通过 SQL 会话表认证和撤销令牌；呼号缓存同样存入 SQL 数据库，不依赖 Redis。

### DevOps

Docker Compose 提供服务器部署组合；Alembic 保存数据库迁移版本。开发及构建命令以仓库脚本为准，步骤见[本地部署](07_本地部署.md)。

## 部署模式

| 模式 | 结构 |
| --- | --- |
| 纯本地（默认） | `DATABASE_MODE=sqlite`，使用本机数据库。源码环境由 Vite（5173 端口）提供网页、FastAPI（8000 端口）提供 API；本地发布包由 FastAPI 在 8000 端口同源提供两者 |
| 局域网 | 浏览器访问服务器前端。Docker Compose 使用 MySQL；Nginx 在 80 端口代理 API 与 WebSocket。用户账户和业务数据保存在服务器 |
| 云服务器 | 业务结构与局域网部署相同，另配域名和 TLS 入口。HTTPS 由部署方配置，应用代码本身不终止 TLS |

部署模式对比表和启动步骤见[本地部署](07_本地部署.md)与[服务器部署](08_服务器部署.md)。

## 核心模块

### 日志管理模块

[`logs.py`](../backend/app/api/v1/logs.py) 负责请求与响应，[`LogService`](../backend/app/services/log_service.py) 处理 CRUD 和概览统计。创建日志时可从激活位置补全台站、位置和本网格，并补全 UTC 日期、时间和 DXCC。

[`ImportExportService`](../backend/app/services/import_export_service.py) 负责 ADI 导入导出。导入按呼号、日期、时间、波段、模式和频率识别已有 QSO，每累计 500 条新记录提交一次。导出支持台站、日期、波段及位置网格筛选。字段范围和合并规则见[API 端点说明](04_API端点说明.md)。

### 用户认证模块

注册、登录和资料更新由 `auth.py` 与 `UserService` 处理。HTTP 和 WebSocket 共用 JWT、用户状态及 SQL 会话校验；管理员接口另检查角色。只签发 access token，无 refresh token 或自动刷新流程。

### 台站与位置管理模块

`StationService` 管理台站呼号，`LocationService` 管理操作位置。用户的第一个未删除位置自动激活；后续激活会先取消该用户其他位置的激活状态。该规则由服务层执行，数据库没有唯一约束。

删除台站会把关联日志备份到回收站，并软删除台站与位置。重建同呼号台站只恢复台站记录，不会同时恢复其位置和日志。

### 呼号查询模块

`CallsignService` 的查询顺序：30 天内的数据库缓存 → 配置凭据后的 QRZ.com → 旧缓存 → 离线 DXCC 推断。离线结果仅用于推断实体。

### DX Cluster 模块

`DXClusterManager` 在每个后端进程中维护一个 Telnet 连接和最多 100 条 spot，向所有订阅者广播，不按用户隔离连接。前端 WebSocket 重连与后端 Telnet 节点重连是两个独立行为。

UDP 使用另一进程内实例，监听后端主机端口，数据仅交付给启动监听的用户。服务器模式仅管理员能启停，默认仅允许本机来源；接收不自动写日志，保存必须调用接口或 WebSocket 保存消息。

### 统计分析模块

`LogService.get_stats` 提供概览；`StatsService` 提供波段、模式、DXCC 图表和交叉矩阵。概览的“已确认”按纸质 QSL 或 LoTW 收到确认计算，DXCC 图表只用 LoTW 收到确认。WAZ 完整统计尚未实现。

### 数据同步模块

`sync.py`、`SyncService` 和 `GitHubService` 提供配置、推拉与历史接口。数据同步与邮件服务目前仅保留接口骨架，暂未接入真实传输（TODO）。

## 安全设计

密码保存为 bcrypt 哈希；客户端通过 Bearer JWT 访问 API。业务服务验证台站和位置的用户归属及关联关系。登出删除当前会话，改密、管理员重置、禁用或删除用户撤销全部会话。

TLS、数据库端口访问范围和运行配置由部署方管理。日志内容未实现数据库静态加密。WebSocket 在连接后通过首条消息认证，不把 JWT 放入 URL。Compose 仅发布前端 80 端口。
